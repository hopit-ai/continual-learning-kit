# kit/

What a GPU partner receives. Nothing here depends on Modal, and nothing here is confidential: it launches public code and summarises results.

| File | What it is |
|---|---|
| `runner.py` | Runs a campaign file row by row on any machine, **with the pilot gate**: a row marked `pilot: true` is judged against bars written in advance, and every later row is refused unless the pilot's latest verdict is PASS. Writes `start.json` before launching and `verdict.json` after; never overwrites; a retry is a new attempt. `plan` prints what would run and executes nothing. |
| `campaigns/toy.yaml`, `toy/fake_train.py` | The smallest campaign that exercises the gate; runs on a laptop in a second. |
| `campaigns/k0-sdpo-toolalpaca.yaml` | Package K0 (batch 0) as a campaign: the smoke is the pilot, the five real runs need it. |
| `run_sdpo_toolalpaca.sh` | Launches the pinned SDPO reference on ToolAlpaca; receipt 201 proves its arguments equal our run 3's record. |
| `run_grpo.sh` | Launches the pinned reference's `baseline_grpo` on any bed's prepared parquet, with `kit/beds/rewards.py` as the reward function. `tests/test_kit_run_grpo.py` proves its arguments are phase 1's own composed GRPO command key for key, and lists the differences it allows (paths, the run's name, the data files, the reward function). `KL=1` adds the trainer's KL-to-reference loss through the three keys the pinned config really has. Records argv, commit, pip freeze and nvidia-smi before starting, refuses to overwrite, merges the final checkpoint with the reference's own merger, and writes `train-summary.json` for a campaign bar to read. |
| `make_report.py` | Turns run directories into `report.md` and `report.json`, the two files a partner sends back. |
| `score_forgetting.py` | Scores a saved model on 300 fixed questions (maths, knowledge, instruction following), one greedy answer each, with the same prompts, decoding and scoring code as our own harness. `generate` needs vLLM and one GPU; `score` and `compare` need nothing. **`compare` only judges two results scored on the same machine** and answers NOT_COMPARABLE otherwise, because cross-machine noise is as large as the 3-point floor (receipt 204). |
| `scorers.py`, `panels/general-v1.jsonl` | Generated by `scripts/make_kit_forgetting_assets.py` from the frozen originals; never hand-edited. |
| `stage_local.py` | Puts inputs on the GPU machine's local disk before the GPU does any work. `pack` (CPU, once): many small files into one deterministic archive with per-file hashes, 16 concurrent readers. `unpack` (GPU start): copy, extract, verify, leave a marker so later runs reuse it. `mirror`: the same for a few large files such as model weights. Use it as a row's `prepare` step and first command. |
| `beds/spider.py`, `beds/spider-split-v1.json` | Spider 1.0 text-to-SQL as a bed. The split file carries only ids and hashes; the partner supplies Spider, and the loader refuses unless every prompt and every database file hashes to what phase 1 froze. The checker executes read-only with a time limit and reproduces phase 1's five published held-out scores exactly (80, 76, 67, 43, 80). Feedback never contains a digit, so no row count can leak. |
| `beds/gsm8k.py` | GSM8K maths as a bed, with a contamination guard: our 100 maths forgetting questions all come from GSM8K's test split, none from train, and the writer refuses if any panel question reaches a training file. Its own 300-question held-out set is disjoint from the panel. |
| `eval_bed.py` | Scores a saved model on ONE bed's held-out questions — Spider's 100, GSM8K's 300, FinQA's test split — in the **same deterministic mode and with the same machine-and-mode fingerprint as `score_forgetting.py`**, whose constants it duplicates on purpose (a test compares the two files and fails if either moves). Writes `bed-score.json` with numeric keys a bar can gate on, plus every answer; `score` re-scores saved answers with no GPU and reproduces phase 1's published 80 of 100. |
| `delta.py` | Subtracts one scoring from another for one key and writes `{delta, a, b, same_machine_flag}` — the numbers the K3 pilot's two bars read ("job A improved by at least 5", "job A then fell by at least 5"). A missing key is a refusal, never a zero. |
| `mix.py` | Builds a stage-B training file that carries a chosen share of job A's QUESTIONS (rehearsal is answered afresh by the model being trained, never replayed). Deterministic given a seed, writes jsonl, parquet and a manifest of counts, achieved share and input hashes; refuses a share outside (0, 0.5] and inputs whose columns differ. |
| `k3_report.py` | The K3 readout: per arm and seed, the old job after A and after B, the new job, and the three panels; per arm the mean and spread over seeds. Refuses to mix scorings made on different machines. |
| `beds/rewards.py` | ONE reward entry point for a mixed run: `compute_score` dispatches on each row's `data_source` to the bed that owns it (loaded by path, because the trainer imports this file by path) and RAISES on a source no bed claims, so half a run can never be silently rewarded zero. |
| `beds/finqa.py` | FinQA as a bed: prompts, a scoring rule that accepts percent-or-decimal and analyst-style rounding, a reward function in the SDPO reference's shape whose feedback never carries the answer, label-problem flags, and a `prepare` step that writes trainer files on CPU. |
| `README-partner.md` | The instructions for package K0, from clone to report. |
| `README-k2.md`, `campaigns/k2-recovery-test.yaml`, `repair/` | Package K2, the recovery test: is a damaged model's lost ability still inside it? `repair/prompts.py` (1,000 everyday prompts with no maths, exam questions or formatting rules), `make_targets.py` (the original model answers them), `train_lora.py` (a 300-step adapter, saved at 50/100/200/300), `merge.py` (tokenizer copied byte for byte), `drift.py` (how far the weights moved), `damage_check.py`, `report.py`. The campaign is generated by `scripts/make_k2_campaign.py`; its first 13 rows are a pilot on a 0.6B model damaged on purpose, and every 8B row is refused until it passes. |
| `README-k3.md`, `campaigns/k3-replay.yaml` | Package K3, the rehearsal test: a Qwen3-1.7B learns SQL, then learns maths in four arms (`none`, `rehearse10`, `rehearse30`, `kl`) over three seeds, and we ask whether rehearsing SQL questions protects SQL. Generated by `scripts/make_k3_campaign.py`; its first rows are a pilot whose two bars — job A must improve, then must be damaged without protection — refuse the whole grid if either fails. |
| `README-k1a.md`, `campaigns/k1a-forgetting-of-k0.yaml` | Package K1a: forgetting scores for the five K0 models, 25 minutes on one GPU, with a pilot that scores the untrained model twice and refuses to continue unless the two agree. |

Rule: **no row runs big unless the same experiment ran small first and passed.** See `docs/plan-open-sota-20260919.md` section 1.
