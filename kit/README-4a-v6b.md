# 4A in v6b — operator procedure

Use this runbook instead of the historical mixed-allocation `a4_payload.sh` /
`a4_run.py` commands, which now refuse real execution. The
[2 November amendment](resources/a4/amendment-20261102.md)
is binding: seeds 101–103, paired t df 2 (4.302653 two-sided, 2.919986 one-sided),
3/3 positive seed means, ≥3/5 positive monthly means (three of months 2–6), all
other bars unchanged. W=D is provisional; the ceiling is **800 GPU-h**.
No result-based stopping, extra dose, or checkpoint selection is added.

The manager imports [v6b-rows.json](resources/a4/v6b-rows.json) into the combined
launch. This standalone wrapper executes the same rows; it never submits jobs.
Each row has group `4a`, one node, explicit GPUs/CPUs/sharing, `time`, command counts,
dependencies and cost basis. Submit `afterok` dependencies as listed and
`afterany` for A4-read, with **`--kill-on-invalid-dep=yes`** on every dependency.
A failed/PENDING upstream row must be resubmitted, then its dependants resubmitted
against the new job ID. Never keep a GPU allocated while awaiting input.

Resource lines (one per scheduled row, plus listed dependencies):

| Phase | sbatch resources | Work |
|---|---|---|
| CPU | `--nodes=1 --gpus=0 --cpus-per-task=8 --time=04:00:00` | Bind, context, ledger, prepare, score-prepare, export, finish, month, read, collect |
| Training | `--nodes=1 --gpus=8 --cpus-per-task=32 --time=01:30:00` | One unchanged 40-update native stage; hard bound 4,500 s |
| Arrival scoring | `--nodes=1 --gpus=1 --cpus-per-task=8 --time=01:00:00` | 11 cells at K=3; hard bound 2,460 s |
| Stage scoring | `--nodes=1 --gpus=1 --cpus-per-task=8 --time=01:30:00` | Incoming/post cells K=3, paired HF NLL K=1; hard bound ≤4,260 s |
| Complete comparison | `--nodes=1 --gpus=1 --cpus-per-task=8 --time=26:00:00` | 418 cells K=3, no NLL; hard bound 84,060 s |

The checked-in rows use planning limits of 4,500 s/training and 600 s per score
or NLL command. Each GPU `time` exceeds its hard bound by at least 15 minutes
or 10%, including full K=3 waves and startup. Choose a partition permitting that
walltime (the comparison needs more than 24 h). CPU times are planning allowances.
Before submission, emit rows using the actual measured stage timing and configured
per-command limits, and use each emitted `time` as its sbatch `--time`:

```bash
"$JOB_PY" -I "$KIT/a4_jobs.py" rows --config "$A4_CONFIG" --out /durable/4a/rows.json
```

The emitted `scheduling_job_limits` must match `binding.json`'s `job_limits`.
Longer measured limits increase these times; they never reduce a hard work bound.

CPU and scoring rows may share nodes; eight-rank training owns all eight allocated
GPUs. The allocation wrapper takes nonblocking per-GPU leases and one idle check;
children inherit `M3_GPU_LOCK_FDS` (I1's S1 name). Exactly one util_watch wraps
execution with `--expect-gpus N` and `UTIL_WATCH_ACTIVE`. Each new attempt creates
a fresh `v6b/attempts/<row>/<nonce>`; PENDING=75, correctness failure=2. No
historical GPU UUID is used for admission. Measured UUID, environment and nonce
are recorded by each scoring process; no proofs copy the frozen assignment.
A verified COMPLETE row exits 0 on resubmission without creating a new attempt.
Its receipt and artifact hashes must verify; a changed completion fails closed.

Chronology: each month archives its contexts, scores the whole arrivals, seals
all arms, releases the checked frozen-collector ledger, and trains eligible
stages. CPU export precedes each stage's incoming/post/NLL scoring job. Both NLL
endpoints are measured together after export, using the exact incoming weights
and fixed schedule; this diagnostic does not affect training or ledger admission.
After month six a fresh complete job scores all **418 scientific cells**, from the archived contexts and saved checkpoints.
The reader takes paired NLL diagnostics from the stage-score jobs.
Only the complete comparison feeds the inferential score contrasts; earlier arrival generations
remain the sole source of training traces. Controls are unseeded and generated
once per exact model/prompt within an allocation. Final technical remeasurement
is required by S4 and is charged explicitly; no cross-job score reuse is allowed.

There are **66 arrival + 189 stage + 418 complete-comparison score cells** (673
upper-bound generation commands before exact prompt/weight deduplication), and
**54 HF NLL endpoints**. Empty-ledger stages retain their registered skips, so
actual command counts may be lower. All 27 native stages retain partials and
native optimizer checkpoints; failed trainers restart at zero on the same seed,
and a complete native dose is exported without retraining. Keep enough durable
space for native states as well as HF weights; CPU exports may run sequentially.

Using the historical 6.3–6.7 GPU-h/stage D+replay timing proxy, training is **170.1–180.9 GPU-h**, or
255.15–271.35 with the registered 1.5 contingency. The unchanged reserves are
60 GPU-h scoring plus 80 overhead/failure; the rounded formula forecasts
**400–450 GPU-h**. The slower 7.73 anchor forecasts 500. These are planning
figures, not SEC timing measurements. Repeated scoring, NLL, loading and failed
allocations consume the same approval. Each GPU attempt reserves its hard bound
before admission; live allocations retain atomic reservations so independent
rows can proceed. Final accounting requires an actual scheduler end from
scontrol/sacct, never a scheduled EndTime. Queue gaps cost zero.
The wrapper charges requested GPUs × full allocation wall time, including idle;
CPU exports cost zero GPU-h. Below-70% rolling utilisation remains a telemetry
risk for HF NLL, model loads and native saves; fixed batches/numerics stay unchanged.
Concurrent scorer process seconds are normalised to the single GPU's held cost,
so three concurrent engines cannot triple the allocation charge. Native states
and CPU merges also require sufficient durable capacity and host RAM; neither
has been qualified on the partner filesystem by this CPU rehearsal.

A4-read runs afterany and returns PENDING if no complete comparison exists.
A4-collect verifies durable omissions, emits the ≤28 MiB archive, and reproduces
the reader from the archive. The receipt includes the amendment/date, exact df/t,
hardware status, all bars, costs and exploratory recurrence status. A mixed
nonce/UUID/environment comparison is labelled UNVERIFIED-HARDWARE, never admitted
as joint success. No script sends messages or submits jobs.
